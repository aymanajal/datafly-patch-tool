# 前端 ZIP 补丁工具

前端模式部署在存放 Nginx 静态目录的服务器上。前后端分机时分别运行工具，通过各自入口访问，不从后端服务器跨机器写文件，也不保存 SSH 密码。

## 做什么

上传包含 `dist/` 的 ZIP，校验完整性、目录结构和 SHA-256，在目标父目录创建独立暂存目录，再将现有 `dist` 重命名为带时间及编号的备份，把新目录切换到正式位置。页面展示操作记录并支持回退。

- 接受任意 ZIP 文件名，但内容必须以 `dist/` 为根且有非空 `dist/index.html`。
- 忽略 `__MACOSX` 和 `.DS_Store`，拒绝路径穿越、符号链接、特殊文件、重复路径和体积超限。
- 上传不改变线上文件，确认执行更新才切换目录。
- 暂存文件设置目录 755、文件 644，确保普通静态文件具备读取权限。
- 不执行任何 Nginx、Java 启停命令，不修改原 Nginx 配置。
- 切换由两次目录重命名完成，可能有短暂访问间隙，不承诺无中断。
- 切换或切换后文件校验失败时尝试恢复原目录；若恢复失败，记录旧目录及现场位置，需人工处理。

文件校验不证明前端版本兼容或业务正常。完成后强制刷新网页，验证登录、本次修复内容及主要功能。

## 安装前检查

在前端服务器确认 Python、工具端口和目标目录：

```bash
python3 --version
ss -lntp | grep ':9081 '
ls -ld /usr/local/nginx/html/dist
ls -lh /usr/local/nginx/html/dist/index.html
```

业务目录以实际 Nginx `root` 配置为准。当前版本目标目录最后一级必须是 `dist`，不支持把符号链接形式的现有 dist 直接作为目标。

## 初始化

把本版本所有源码（包括新增的 `frontend.py`）上传到该服务器的 `/opt/datafly-patch-tool`。首次安装执行：

```bash
cd /opt/datafly-patch-tool
python3 server.py --init
```

只在新的前端工具实例配置中设置以下字段，保留已有密码摘要：

```json
{
  "deployment_type": "frontend",
  "frontend_dir": "/usr/local/nginx/html/dist",
  "bind": "127.0.0.1",
  "target_label": "前端服务器",
  "port": 9081,
  "allowed_peers": ["127.0.0.1"]
}
```

上面是字段示例，不能整体替换完整 `config.json`。浏览器直连时，`bind` 填服务器实际地址，`allowed_peers` 增加实际客户端来源 IP，和后端工具的配置方式一致。`app_dir`、`app_port` 在前端模式不参与部署；前端目标由 `frontend_dir` 决定。不要把已有后端实例改成前端模式。

```bash
python3 server.py --check
python3 server.py
```

检查输出应包含 `deployment_type: frontend`、正确目录及 `frontend_ready: true`。前台启动后访问 `http://服务器IP:9081/patch-tool/`，页面应显示“前端补丁”。先确认登录及目录，再安排更新。

后台服务安装方式与 [部署说明](../DEPLOY.md) 相同；该服务器上工具独立读取自己的配置，不会自动修改其他服务器的后端工具。服务端仍兼容 Python 3.7，无 pip 依赖。

## 备份与回退

工具产生的备份名称为 `dist-backup-时间-唯一编号`，存放在 dist 同级目录。还可以识别手工流程产生的 `dist-backup-年月日_时分秒` 备份，不会列出所有任意目录。

回退会复制选中备份到暂存目录、逐文件校验，再备份当前 dist 并切换；来源备份仍然保留。不会自动删除旧备份，注意磁盘容量。

更新期间不要手工替换前端目录或重启工具。工具互斥锁不能阻止其他人直接操作文件。若机器断电或工具在两次重命名之间终止，可能需从同级备份目录人工恢复；重启后的“监控中断”不是成功证明。

此模式不主动清理浏览器缓存、不刷新 CDN，不保留旧版资源在新 dist 内；旧页面可能因资源文件名变化需要强制刷新。
