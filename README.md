# 影像前后端补丁更新工具

每次更新影像后端，都要登录服务器、上传 JAR、手动备份和改名、停止服务、启动服务，再检查状态。步骤重复，容易传错目录、覆盖备份，更新失败后找旧包也不方便。因此做了这个工具，把重复操作收进一个网页。

**选择补丁 → 上传校验 → 确认更新 → 自动备份与启停 → 检查结果。**

支持后端 JAR 和前端 dist ZIP 两种模式，分别部署在对应业务文件所在的服务器上。

这是一个部署在 Linux 应用服务器上的轻量工具，使用 Python 标准库，无需安装 pip 依赖。可以通过浏览器直接访问，Nginx 为可选项。

## 能做什么

- 管理密码登录、来源 IP 限制、会话及 CSRF 校验。
- 上传任意名称的后端 JAR，例如 `1.jar`；执行更新时统一替换为 `datafly-admin.jar`。
- 校验 JAR、Manifest / Main-Class 和 SHA-256；仅上传不会修改正式包。
- 先暂存并备份旧包，再停止、替换、启动；备份名带时间和唯一编号。
- 检查目标 Java 进程及配置的后端端口，保留操作时间线和启停脚本输出。
- 查看备份并回退；回退前也会备份当前版本。
- 同一时间只执行一个更新任务，失败停止后续步骤。
- 通过 systemd 后台运行，关闭 SSH 终端后仍可访问。

前端 ZIP 模式新增：上传、检查 `dist/index.html`、忽略 macOS 元数据、备份与切换目录、失败恢复及备份回退。部署方法见 [前端补丁工具](docs/FRONTEND.md)。不重启 Nginx 或后端。

## 工作方式

```text
浏览器 → 更新工具（独立端口）→ 本机 datafly.sh → 影像后端
                ├── 上传文件与校验
                ├── 当前包备份
                └── 更新记录与回退
```

工具独立于影像后端运行。影像后端重启时，更新页面仍可显示进度。浏览器关闭不取消已提交任务。

## 开始使用

详细步骤见 [部署说明](DEPLOY.md)。需要 Linux、Python 3.7+、Bash，以及现有 `datafly.sh`。Python 3.7 已结束支持；兼容旧环境不代表建议新环境继续安装旧版本。

```bash
cd /opt/datafly-patch-tool
python3 server.py --init
# 按部署说明修改 config.json 中的地址、目录、后端端口和允许访问的客户端 IP。
python3 server.py --check
python3 server.py
```

初始化默认仅监听 `127.0.0.1:9081`，不再固化任何现场内网地址。直连时需要配置服务器实际 IP 和客户端实际来源 IP。路径固定以 `/patch-tool/` 结尾。

`--check` 检查部署目录、启动脚本并报告当前进程和端口，不停止或更新后端。运行状态只是输出信息，执行命令成功不等于后端已经运行；必须同时核对 `pids` 和 `port_open`。

## 使用边界

进程与 TCP 端口连续稳定不等于业务验证通过，更新后还需要访问影像功能。工具不自动删除备份、不强杀 Java、不自动反复重启或回退。备份仍在同一台服务器上，不能代替异机备份。

只用于受控运维网络。HTTP 入口没有 TLS 加密；如需加密，应配置 HTTPS 入口或安全隧道。工具能够替换并运行 JAR，登录者应具有应用发布权限。使用与原影像服务相同的账号及 Java 环境。

上传 GitHub 前见 [发布准备](docs/GITHUB.md)。本仓库暂未指定开源许可证；如需允许他人按明确条款使用或分发，请先选择许可证。
